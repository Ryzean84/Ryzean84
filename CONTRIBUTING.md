# Contributing

Thank you for helping improve this project.

## Before contributing

1. Read the README and SECURITY policy.
2. Open an issue before substantial changes so scope and direction can be agreed.
3. Keep changes focused and explain the problem they solve.
4. Do not submit credentials, personal data, private intelligence, or data collected without authorization.

## Quality expectations

- Add or update tests when behavior changes.
- Document configuration, dependencies, and operational assumptions.
- Prefer minimal dependencies and reproducible setup instructions.
- Never claim a test, audit, deployment, or validation passed unless it was actually run.

## Pull requests

Describe the change, rationale, test commands and results, risks, and any migration steps. Keep pull requests small enough to review.
